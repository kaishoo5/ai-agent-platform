Nova Support 개발 회의록

회의 일시: 2026년 7월 24일 10:00
참석자: 김개발, 이기획, 박보안, 최운영

1. 현재 진행 상황
- 채팅방 생성, 삭제, 목록 조회 기능 구현 완료
- 사용자 메시지와 AI 메시지의 MariaDB 저장 완료
- Ollama qwen3:4b 연동 및 SSE 스트리밍 완료
- 답변 중지, 다시 생성, 코드 복사 기능 구현 완료
- TXT 파일 업로드 및 파일 내용을 프롬프트에 포함하는 기능 테스트 완료
- 테스트 파일명: test22.txt
- 파일 ID가 채팅 스트리밍 요청의 fileIds 배열에 정상 포함되는 것을 확인함

2. 결정 사항
- 파일 프롬프트 생성 로직을 ChatStreamService에서 분리해 FilePromptBuilder 클래스로 관리한다.
- 파일별 최대 입력 길이는 20,000자로 제한한다.
- 여러 파일의 전체 입력 길이는 60,000자로 제한한다.
- DB에는 사용자가 입력한 원문 질문만 저장하고, 파일 내용이 포함된 프롬프트는 Ollama 호출에만 사용한다.
- fileIds의 전달 순서를 유지해 프롬프트에서도 같은 순서로 파일을 배치한다.
- 다른 채팅방에 속한 파일 ID가 들어오면 HTTP 400 오류를 반환한다.

3. 미해결 항목
- 업로드 파일과 개별 채팅 메시지를 연결하는 message_id 구조는 아직 적용하지 않았다.
- 새로고침 후 과거 메시지에 첨부파일 이름을 표시하는 기능은 미구현 상태다.
- PDF, DOCX, XLSX, CSV 파서는 아직 지원하지 않는다.
- 대용량 문서를 위한 벡터 검색 기반 RAG는 향후 단계로 보류한다.
- 파일 읽기 실패 시 사용자 화면에 표시할 오류 메시지 형식이 확정되지 않았다.

4. 일정
- 7월 24일: FilePromptBuilder 분리 및 길이 제한 적용
- 7월 25일: 다중 파일 분석 테스트와 예외 처리 보완
- 7월 28일: 메시지와 첨부파일 연결 구조 설계
- 8월 첫째 주: PDF 지원 검토
- 8월 둘째 주: 운영 배포 환경 점검

5. 테스트 시나리오
- 요구사항 파일과 회의록 파일을 동시에 첨부한다.
- AI에게 두 파일의 공통 내용, 완료된 기능, 미해결 항목을 구분해 달라고 요청한다.
- 출시 목표일, 지원 확장자, 입력 길이 제한을 질문한다.
- 회의록에는 출시 목표일이 직접 기재되어 있지 않으므로 요구사항 파일을 근거로 답하는지 확인한다.
- message_id 연결 기능이 완료되었다고 잘못 답하지 않는지 확인한다.

6. 위험 요소
- 긴 파일을 그대로 LLM에 전달하면 컨텍스트 한도를 초과할 수 있다.
- 파일 내용을 사용자 질문과 함께 DB에 저장하면 채팅 기록이 불필요하게 커질 수 있다.
- 파일 소유 채팅방을 확인하지 않으면 다른 사용자의 자료가 노출될 가능성이 있다.
